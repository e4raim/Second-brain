# Правила работы с библиотекой (для Claude)

Это база знаний компании, а не код. Язык всех заметок — русский. Структура описана в README.md.

## Когда пользователь загружает материал

1. Сохранить оригинал (или расшифровку / текст) в `inbox/<тип>/` с именем `ГГГГ-ММ-ДД-краткое-название.<ext>`.
2. Создать конспект в `sources/` по шаблону `templates/source.md`.
3. Разнести идеи по `knowledge/` по шаблону `templates/topic.md`:
   - сначала искать существующую тему (grep по заголовкам и тегам) и дополнять её;
   - новая тема — только если такой ещё нет; одна тема = один файл;
   - у каждого тезиса указывать источник ссылкой на файл в `sources/`;
   - если источники противоречат друг другу — блок «⚠️ Расхождение», не выбирать молча;
   - практика компании важнее внешних книг: внешнее помечать как «из внешнего источника».
4. Скрипты → `knowledge/05-scripts/` по `templates/script.md`; диалоги → `knowledge/06-dialog-reviews/` по `templates/dialog-review.md`.
5. Обновить треки в `tracks/` (добавить тему в нужный трек и место) и `knowledge/INDEX.md`.
6. Коротко отчитаться пользователю: что создано, что дополнено, какие вопросы/противоречия всплыли.

## Персональные данные

В диалогах и скриптах заменять имена клиентов, телефоны, адреса и суммы конкретных сделок на обезличенные (Клиент, Агент, [телефон]), если пользователь не сказал иначе.

## Стиль

- Коротко и прикладно: «что делать» и «как сказать», примеры фраз, чек-листы.
- Для стажёра — объяснять термины; для РОПа/руководителя — акцент на систему, метрики, контроль.
- Главы книги (`book/`) пишутся живым связным текстом, а не списком тезисов.

## Git

Изменения коммитить осмысленными сообщениями на русском («Добавлен конспект: …»).
